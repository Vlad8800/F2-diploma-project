# PostgreSQL 16: схема та перевірка обмежень

`migrations/001_initial_schema.sql` створює 17 таблиць із ERD підрозділу 2.4, PK, FK, UNIQUE, CHECK та індексами. `tests/001_constraints_smoke.sql` перевіряє прийнятні записи й відхилення дубля коду, хибного статусу, міжпроєктного ребра, самопетлі, повторного відкритого автоматичного QA-завдання, а також незмінність ревізій і аудиту. Тест відкочує всі вставлені дані.

На порожній тестовій БД PostgreSQL 16 запустіть із кореня репозиторію:

```powershell
psql -X -v ON_ERROR_STOP=1 -d usetrace_test -f db/migrations/001_initial_schema.sql
psql -X -v ON_ERROR_STOP=1 -d usetrace_test -f db/tests/001_constraints_smoke.sql
```

Базу `usetrace_test` необхідно створити заздалегідь. Міграцію застосовують один раз на порожній базі. Не запускати її безпосередньо на продукційній БД.

Межі SQL: заборону довших циклів DAG, циклів WBS, правила кінцевого WBS-вузла, відповідність поточної версії її знімку, зміну `project_revision` разом з однією подією аудиту й права доступу OIDC перевіряє транзакційний шар застосунку. `CHECK` не може замінити ці міжрядкові та процесні правила. Міграція не створює прикладний API і не підтверджує поведінку сервісу. Для незмінних таблиць додані тригери; права прикладної ролі слід налаштувати окремо під час розгортання.

Стан перевірки: поля 17 таблиць звірено статично з Mermaid ERD. Виконання `psql` у поточному середовищі не відбулося через відсутність PostgreSQL-клієнта й працюючого сервера. Результат smoke-тестів потрібно зафіксувати після запуску у тестовій БД.
